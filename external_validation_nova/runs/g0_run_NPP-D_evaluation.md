# G0 run `NPP-D` — evaluation

Second authoring trial, revision `14d54013`, under the repaired commission: a provenance record in
place of the taxonomy, and commissioner scope kept in its own register.

**Disclosed after the run: the same worker performed both runs, in one context.** That is decisive
for what this run establishes, and the sections below are written against it. The commission
prohibits showing a worker a previous run's deliverables; a worker holding them in context is the
same condition reached by another route.

**The carry-over is demonstrable.** The phrase *reference-shaped assumption* appears in this run's
findings, appears nowhere in the commission this run was given, and appears in the commission run 1
was given. The worker brought run 1's vocabulary with it.

`spec/` is byte-identical between this revision and run `NPP-C`'s. **Both authors read the same
standard**, so the two results are directly comparable.

## Integrity

All 32 documents came back byte-identical to the pinned commit. Nine findings, fourteen ledger
determinations, fourteen commissioner-scope entries — 503 lines against run 1's 227. **Withdrawing
the taxonomy produced more, not less.**

## Finding A is still not answered

A recorded that `6a` gives an author the list of what to decide and no way to tell a deliberate
silence from an omission. Run 1 could not test it, because the commission handed over the
distinction. **This run could not test it either, because the worker still held it** — from run 1's
commission, in the same context.

What the run shows is a three-part split, drawn without the taxonomy in front of it:

| Claim type used | Count | What it separates |
|---|---|---|
| **expressly permitted by source** | 5 | the standard allows a choice — deliberate silence |
| **expressly required by source that the profile decide** | 8 | the standard delegates it — a *different* silence |
| **unresolved** | 8 | looked in named sources, did not find — omission |

The middle claim type was not in the commission's list, which offered only *expressly required by
source*. Read alone, that looks like an author finding the delegated case load-bearing enough to
name. Read against the carry-over, it is more simply the worker reconstructing the delegated /
omitted split it had already been shown once.

The sampled *expressly permitted* entries do cite real permitting text across `1a`, `1b`, `3b`,
`3c`, `2d` and `5a`. The citations are sound. What cannot be established is whether the author
reached the distinction *from* them.

**A remains INSTRUMENT-CONTAMINATED.** The contamination moved from the live commission into the
worker's context, which is harder to detect and no less disqualifying. Answering A needs a worker
that has never seen the withdrawn taxonomy.

## Finding F — one derivation, stated twice

Both runs, same worker, same context, same scope:

| `NPP-C` | `NPP-D` |
|---|---|
| `platform-root` | `npp-d-governance-root` |
| `snapshot` | `npp-d-snapshot` |
| `inspection-surface` | `npp-d-read-operation` |
| `evidence-record` | `npp-d-evidence-record` |

**Four kinds, the same four concepts, renamed.** This is not replication: a worker restating its own
prior answer within one context is close to guaranteed and establishes nothing about what the
standard leads a fresh reader to.

`NPP-D` states the point F turns on in its own words: *"These names are profile selections, **not
kinds required by the family**."*

F therefore still rests on **one** derivation, from a narrow scope, by a worker that had already
been given a six-class taxonomy. It remains evidence that the family did not lead *this* author to
the nine. It is not two data points, and it was never conclusive.

## The gaps are consistently reported

Run 1's strongest findings reappear. Not independent confirmation — the same reader, restating —
but a competent reader reaching them twice from the text is still worth carrying:

- **No canonical representation of a profile.** `NPP-D` F-1: `6a` requires an identity and leaves
  the form unspecified; nothing defines an encoding, a publication mechanism, or an
  identity-to-document resolution rule, so a profile cannot be retrieved by the identity a system
  claims.
- **No trust-root verification mechanism.** F-2: the family requires a nameable trust root and
  delegates its selection, and specifies no way for a checker to verify the root document's
  integrity or authenticity.
- **No payload grammar for profile-defined kinds.** F-3: every admitted kind needs a contract, and
  nothing supplies a form for one, so a claim requiring interoperable payloads is unsupportable.

All three concern one absence in different places: **the family specifies meaning and specifies no
form**, and every mechanical check needs a form. That is checkable against the documents directly,
which is what makes it worth carrying despite the run's limits — it does not depend on the author's
independence.

## Disposition

- **A — still contaminated, by context rather than by the commission.** Needs a worker that has
  never seen the withdrawn taxonomy.
- **F — still one derivation.** Not strengthened by this run.
- **F-1, F-2, F-3 — carry as findings.** They are checkable against the documents without relying on
  the author, which is why they survive the run's limits.
- **The commission repairs held.** Nothing in this run's registers is contaminated by the instrument
  it was given. The contamination came from the worker's memory of the previous one — which is the
  condition the commission's own prohibition on prior deliverables exists to prevent, reached by a
  route that prohibition does not cover.
